## Edge Function and security review

`development-member-admin` version 1 was deployed only to the development project with `verify_jwt=true`. Its artifact SHA-256 is `e8897ddb6f2272eb7376d8172cec1d2322313d65f274ef0cf8e565e4b7db6690`. Supabase reports the function deployment `ACTIVE`; **member provisioning remains disabled** through the runtime kill switch, which defaults false.

The function accepts only a bounded strict JSON POST and pins the project URL. It rejects foreign origins, verifies the bearer token with live Auth, requires confirmed email, active Owner membership in the requested organization, and a current trusted database session. It constructs a privileged Auth-only adapter only after those checks and the kill switch. Database reads/writes use the caller's JWT and RLS, never the admin client. Public functions remain invoker-only; private definer helpers retain empty search paths.

Supabase-managed runtime key bindings supply the privileged key. Keys are neither retrieved to this workspace nor sent to Netlify. No broadening of Netlify secret scopes is required. The function uses the same portable provisioning core as the server actions, generates 192-bit temporary credentials, creates unconfirmed identities with a protected provisioning marker, and sends no invitation. Native member-requested email confirmation, password-fingerprint change, 48-hour credential expiry, trusted Auth session creation and subsequent fresh login remain mandatory.

Provisioning reserves a seat under an organization row lock before Auth creation. Pending seats count toward the two-member cap; duplicate operation IDs do not create another identity or recover a passcode. Ambiguous Auth outcomes retain the seat for reconciliation. Management operations retain the existing shared 10/hour and 30/day database limits.

Development reset claims add a unique per-member in-flight lease and immutable operation ID. Replays never call Auth again. A five-minute finalization deadline, protected identity marker and changed provider password fingerprint are required. Expired/uncertain claims stay blocked for manual reconciliation; they are not automatically recycled while a delayed Auth operation could still complete. Access is revoked before the password provider is called. Credentials are returned once, only after successful attachment/finalization, with `Cache-Control: no-store`; provider errors are sanitized and never logged.

The app transport is server-only, checks the exact development site, project and origin, and performs no automatic retries. The production adapter remains gated separately. CI now also type-checks the pinned Deno runtime and frozen Edge dependency lock.
